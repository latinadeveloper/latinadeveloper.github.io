Plantillas de Aplicaciones Rails

Las plantillas de aplicaciones son archivos Ruby simples que contienen un DSL para agregar gemas, inicializadores, etc., a tu proyecto Rails recién creado o a un proyecto Rails existente.

Después de leer esta guía, sabrás:

  • Cómo usar plantillas para generar/personalizar aplicaciones Rails.
  • Cómo escribir tus propias plantillas de aplicaciones reutilizables usando la API de plantillas de Rails.

1 Uso

Para aplicar una plantilla, necesitas proporcionar al generador de Rails la ubicación de la plantilla que deseas aplicar usando la opción -m. Esto puede ser un camino a un archivo o una URL.

$ rails new blog -m ~/template.rb
$ rails new blog -m http://example.com/template.rb

Puedes usar el comando app:template de Rails para aplicar plantillas a una aplicación Rails existente. La ubicación de la plantilla debe pasarse a través de la variable de entorno LOCATION. Nuevamente, esto puede ser un camino a un archivo o una URL.

$ bin/rails app:template LOCATION=~/template.rb
$ bin/rails app:template LOCATION=http://example.com/template.rb

2 API de Plantillas

La API de plantillas de Rails es fácil de entender. Aquí tienes un ejemplo de una plantilla típica de Rails:

# template.rb
generate(:scaffold, "person name:string")
route "root to: 'people#index'"
rails_command("db:migrate")

after_bundle do
  git :init
  git add: "."
  git commit: %Q{ -m 'Initial commit' }
end

Las siguientes secciones describen los métodos principales proporcionados por la API:

2.1 gem(*args)

Agrega una entrada gem para la gema suministrada al Gemfile de la aplicación generada.

Por ejemplo, si tu aplicación depende de las gemas bj y nokogiri:

gem "bj"
gem "nokogiri"

Ten en cuenta que este método solo agrega la gema al Gemfile; no instala la gema.

También puedes especificar una versión exacta:

gem "nokogiri", "~> 1.16.4"

Y también puedes agregar comentarios que se añadirán al Gemfile:

gem "nokogiri", "~> 1.16.4", comment: "Añadir la gema nokogiri para el análisis XML"

2.2 gem_group(*names, &block)

Envuelve entradas de gemas dentro de un grupo.

Por ejemplo, si deseas cargar rspec-rails solo en los grupos development y test:

gem_group :development, :test do
  gem "rspec-rails"
end

2.3 add_source(source, options={}, &block)

Agrega la fuente dada al Gemfile de la aplicación generada.

Por ejemplo, si necesitas obtener una gema de "http://gems.github.com":

add_source "http://gems.github.com"

Si se proporciona un bloque, las entradas de gemas en el bloque se envuelven en el grupo de la fuente.

add_source "http://gems.github.com/" do
  gem "rspec-rails"
end

2.4 environment/application(data=nil, options={}, &block)

Agrega una línea dentro de la clase Application para config/application.rb.

Si se especifica options[:env], la línea se agrega al archivo correspondiente en config/environments.

environment 'config.action_mailer.default_url_options = {host: "http://yourwebsite.example.com"}', env: 'production'

Un bloque puede usarse en lugar del argumento data.

2.5 vendor/lib/file/initializer(filename, data = nil, &block)

Agrega un inicializador al directorio config/initializers de la aplicación generada.

Digamos que te gusta usar Object#not_nil? y Object#not_blank?:

initializer 'bloatlol.rb', <<-CODE
  class Object
    def not_nil?
      !nil?
    end

    def not_blank?
      !blank?
    end
  end
CODE

De manera similar, lib() crea un archivo en el directorio lib/ y vendor() crea un archivo en el directorio vendor/.

Incluso hay file(), que acepta una ruta relativa desde Rails.root y crea todos los directorios/archivos necesarios:

file 'app/components/foo.rb', <<-CODE
  class Foo
  end
CODE

Eso creará el directorio app/components y pondrá foo.rb allí.

2.6 rakefile(filename, data = nil, &block)

Crea un nuevo archivo rake bajo lib/tasks con las tareas suministradas:

rakefile("bootstrap.rake") do
  <<-TASK
    namespace :boot do
      task :strap do
        puts "¡Me gustan las botas!"
      end
    end
  TASK
end

Lo anterior crea lib/tasks/bootstrap.rake con una tarea rake boot:strap.

2.7 generate(what, *args)

Ejecuta el generador de Rails suministrado con los argumentos dados.

generate(:scaffold, "person", "name:string", "address:text", "age:number")

2.8 run(command)

Ejecuta un comando arbitrario. Al igual que los acentos graves. Digamos que deseas eliminar el archivo README.rdoc:

run "rm README.rdoc"

2.9 rails_command(command, options = {})

Ejecuta el comando suministrado en la aplicación Rails. Digamos que deseas migrar la base de datos:

rails_command "db:migrate"

También puedes ejecutar comandos con un entorno Rails diferente:

rails_command "db:migrate", env: 'production'

También puedes ejecutar comandos como superusuario:

rails_command "log:clear", sudo: true

También puedes ejecutar comandos que deberían abortar la generación de la aplicación si fallan:

rails_command "db:migrate", abort_on_failure: true

2.10 route(routing_code)

Agrega una entrada de enrutamiento al archivo config/routes.rb. En los pasos anteriores, generamos un scaffold de persona y también eliminamos README.rdoc. Ahora, para hacer que PeopleController#index sea la página predeterminada para la aplicación:

route "root to: 'person#index'"

2.11 inside(dir)

Te permite ejecutar un comando desde el directorio dado. Por ejemplo, si tienes una copia de edge rails que deseas enlazar simbólicamente desde tus nuevas aplicaciones, puedes hacer esto:

inside('vendor') do
  run "ln -s ~/commit-rails/rails rails"
end

2.12 ask(question)

ask() te da la oportunidad de obtener comentarios del usuario y usarlos en tus plantillas. Digamos que quieres que tu usuario nombre la nueva biblioteca brillante que estás agregando:

lib_name = ask("¿Cómo quieres llamar a la biblioteca brillante?")
lib_name << ".rb" a menos que lib_name.index(".rb")

lib lib_name, <<-CODE
  class Shiny
  end
CODE

2.13 yes?(question) o no?(question)

Estos métodos te permiten hacer preguntas desde las plantillas y decidir el flujo basado en la respuesta del usuario. Digamos que deseas pedir al usuario que ejecute migraciones:

rails_command("db:migrate") if yes?("¿Ejecutar migraciones de base de datos?")
# no?(question) actúa justo al contrario.

2.14 git(:command)

Las plantillas de Rails te permiten ejecutar cualquier comando git:

git :init
git add: "."
git commit: "-a -m 'Initial commit'"

2.15 after_bundle(&block)

Registra una devolución de llamada para ser ejecutada después de que las gemas se agrupen y se generen los binstubs. Útil para agregar archivos generados al control de versiones:

after_bundle do
  git :init
  git add: '.'
  git commit: "-a -m 'Initial commit'"
end

Las devoluciones de llamada se ejecutan incluso si se ha pasado --skip-bundle.

3 Uso Avanzado

La plantilla de aplicación se evalúa en el contexto de una instancia de Rails::Generators::AppGenerator. Usa la acción apply proporcionada por Thor.

Esto significa que puedes extender y cambiar la instancia para que se ajuste a tus necesidades.

Por ejemplo, sobrescribiendo el método source_paths para contener la ubicación de tu plantilla. Ahora los métodos como copy_file aceptarán rutas relativas a la ubicación de tu plantilla.

def source_paths
  [__dir__]
end
