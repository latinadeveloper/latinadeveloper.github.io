Los fundamentos de crear plugins de Rails

Un plugin de Rails es una extensión o modificación del núcleo del framework. Los plugins proporcionan:

  • Una forma para que los desarrolladores compartan ideas de vanguardia sin dañar la base de código estable.
  • Una arquitectura segmentada para que las unidades de código puedan ser corregidas o actualizadas en su propio calendario de lanzamientos.
  • Una salida para los desarrolladores principales para que no tengan que incluir cada nueva característica genial.

Después de leer esta guía, sabrás:

  • Cómo crear un plugin desde cero.
  • Cómo escribir y ejecutar pruebas para el plugin.

Esta guía describe cómo construir un plugin impulsado por pruebas que:

  • Extienda clases centrales de Ruby como Hash y String.
  • Agregue métodos a ApplicationRecord en la tradición de los plugins acts_as.
  • Te dé información sobre dónde poner generadores en tu plugin.

Para el propósito de esta guía, finjamos por un momento que eres un ávido observador de aves. Tu ave favorita es el Yaffle, y quieres crear un plugin que permita a otros desarrolladores compartir la bondad del Yaffle.

1 Configuración

Actualmente, los plugins de Rails se construyen como gemas, plugins gemificados. Pueden ser compartidos a través de diferentes aplicaciones Rails usando RubyGems y Bundler si se desea.

1.1 Generar un Plugin Gemificado

Rails viene con un comando rails plugin new que crea un esqueleto para desarrollar cualquier tipo de extensión de Rails con la capacidad de ejecutar pruebas de integración usando una aplicación dummy de Rails. Crea tu plugin con el comando:

$ rails plugin new yaffle

Consulta el uso y las opciones pidiendo ayuda:

$ rails plugin new --help

2 Probar tu Plugin Recién Generado

Navega al directorio que contiene el plugin y edita yaffle.gemspec para reemplazar cualquier línea que tenga valores TODO:

spec.homepage    = "http://example.com"
spec.summary     = "Resumen de Yaffle."
spec.description = "Descripción de Yaffle."

...

spec.metadata["source_code_uri"] = "http://example.com"
spec.metadata["changelog_uri"] = "http://example.com"

Luego ejecuta el comando bundle install.

Ahora puedes ejecutar las pruebas usando el comando bin/test, y deberías ver:

$ bin/test
...
1 runs, 1 assertions, 0 failures, 0 errors, 0 skips

Esto te dirá que todo se generó correctamente y estás listo para empezar a agregar funcionalidad.

3 Extender Clases Centrales

Esta sección explicará cómo agregar un método a String que estará disponible en cualquier lugar de tu aplicación Rails.

En este ejemplo, agregarás un método a String llamado to_squawk. Para comenzar, crea un nuevo archivo de prueba con algunas afirmaciones:

# yaffle/test/core_ext_test.rb

require "test_helper"

class CoreExtTest < ActiveSupport::TestCase
  def test_to_squawk_prepends_the_word_squawk
    assert_equal "squawk! Hello World", "Hello World".to_squawk
  end
end

Ejecuta bin/test para ejecutar la prueba. Esta prueba debería fallar porque no hemos implementado el método to_squawk:

$ bin/test
E

Error:
CoreExtTest#test_to_squawk_prepends_the_word_squawk:
NoMethodError: undefined method `to_squawk' for "Hello World":String


bin/test /ruta/a/yaffle/test/core_ext_test.rb:4

.

Finished in 0.003358s, 595.6483 runs/s, 297.8242 assertions/s.
2 runs, 1 assertions, 0 failures, 1 errors, 0 skips

Genial, ahora estás listo para comenzar el desarrollo.

En lib/yaffle.rb, agrega require "yaffle/core_ext":

# yaffle/lib/yaffle.rb

require "yaffle/version"
require "yaffle/railtie"
require "yaffle/core_ext"

module Yaffle
  # Tu código va aquí...
end

Finalmente, crea el archivo core_ext.rb y agrega el método to_squawk:

# yaffle/lib/yaffle/core_ext.rb

class String
  def to_squawk
    "squawk! #{self}".strip
  end
end

Para probar que tu método hace lo que dice que hace, ejecuta las pruebas unitarias con bin/test desde tu directorio de plugins.

$ bin/test
...
2 runs, 2 assertions, 0 failures, 0 errors, 0 skips

Para ver esto en acción, cambia al directorio test/dummy, inicia bin/rails console, y comienza a graznar:

irb> "Hello World".to_squawk
=> "squawk! Hello World"

4 Agregar un Método "acts_as" a Active Record

Un patrón común en los plugins es agregar un método llamado acts_as_something a los modelos. En este caso, quieres escribir un método llamado acts_as_yaffle que agregue un método squawk a tus modelos de Active Record.

Para comenzar, configura tus archivos para que tengas:

# yaffle/test/acts_as_yaffle_test.rb

require "test_helper"

class ActsAsYaffleTest < ActiveSupport::TestCase
end

# yaffle/lib/yaffle.rb

require "yaffle/version"
require "yaffle/railtie"
require "yaffle/core_ext"
require "yaffle/acts_as_yaffle"

module Yaffle
  # Tu código va aquí...
end

# yaffle/lib/yaffle/acts_as_yaffle.rb

module Yaffle
  module ActsAsYaffle
  end
end

4.1 Agregar un Método de Clase

Este plugin esperará que hayas agregado un método a tu modelo llamado last_squawk. Sin embargo, los usuarios del plugin podrían haber definido ya un método en su modelo llamado last_squawk que usan para otra cosa. Este plugin permitirá que el nombre sea cambiado agregando un método de clase llamado yaffle_text_field.

Para comenzar, escribe una prueba fallida que muestre el comportamiento que te gustaría:

# yaffle/test/acts_as_yaffle_test.rb

require "test_helper"

class ActsAsYaffleTest < ActiveSupport::TestCase
  def test_a_hickwalls_yaffle_text_field_should_be_last_squawk
    assert_equal "last_squawk", Hickwall.yaffle_text_field
  end

  def test_a_wickwalls_yaffle_text_field_should_be_last_tweet
    assert_equal "last_tweet", Wickwall.yaffle_text_field
  end
end

Esto nos dice que no tenemos los modelos necesarios (Hickwall y Wickwall) que estamos tratando de probar. Podemos generar fácilmente estos modelos en nuestra aplicación "dummy" de Rails ejecutando los siguientes comandos desde el directorio test/dummy:

$ cd test/dummy
$ bin/rails generate model Hickwall last_squawk:string
$ bin/rails generate model Wickwall last_squawk:string last_tweet:string

Ahora puedes crear las tablas de base de datos necesarias en tu base de datos de pruebas navegando a tu aplicación dummy y migrando la base de datos. Primero, ejecuta:

$ cd test/dummy
$ bin/rails db:migrate

Mientras estás aquí, cambia los modelos Hickwall y Wickwall para que sepan que deben actuar como yaffles.

# test/dummy/app/models/hickwall.rb

class Hickwall < ApplicationRecord
  acts_as_yaffle
end

# test/dummy/app/models/wickwall.rb

class Wickwall < ApplicationRecord
  acts_as_yaffle yaffle_text_field: :last_tweet
end

También agregaremos código para definir el método acts_as_yaffle.

# yaffle/lib/yaffle/acts_as_yaffle.rb

module Yaffle
  module ActsAsYaffle
    extend ActiveSupport::Concern

    class_methods do
      def acts_as_yaffle(options = {})
      end
    end
  end
end

# test/dummy/app/models/application_record.rb

class ApplicationRecord < ActiveRecord::Base
  include Yaffle::ActsAsYaffle

  self.abstract_class = true
end

Cada vez más cerca... Ahora implementaremos el código del método acts_as_yaffle para que las pruebas pasen.

# yaffle/lib/yaffle/acts_as_yaffle.rb

module Yaffle
  module ActsAsYaffle
    extend ActiveSupport::Concern

    class_methods do
      def acts_as_yaffle(options = {})
        cattr_accessor :yaffle_text_field, default: (options[:yaffle_text_field] || :last_squawk).to_s
      end
    end
  end
end

# test/dummy/app/models/application_record.rb

class ApplicationRecord < ActiveRecord::Base
  include Yaffle::ActsAsYaffle

  self.abstract_class = true
end

4.2 Agregar un Método de Instancia

Este plugin agregará un método llamado 'squawk' a cualquier objeto de Active Record que llame a acts_as_yaffle. El método 'squawk' simplemente establecerá el valor de uno de los campos en la base de datos.

Para comenzar, escribe una prueba fallida que muestre el comportamiento que te gustaría:

# yaffle/test/acts_as_yaffle_test.rb
require "test_helper"

class ActsAsYaffleTest < ActiveSupport::TestCase
  def test_a_hickwalls_yaffle_text_field_should_be_last_squawk
    assert_equal "last_squawk", Hickwall.yaffle_text_field
  end

  def test_a_wickwalls_yaffle_text_field_should_be_last_tweet
    assert_equal "last_tweet", Wickwall.yaffle_text_field
  end

  def test_hickwalls_squawk_should_populate_last_squawk
    hickwall = Hickwall.new
    hickwall.squawk("Hello World")
    assert_equal "squawk! Hello World", hickwall.last_squawk
  end

  def test_wickwalls_squawk_should_populate_last_tweet
    wickwall = Wickwall.new
    wickwall.squawk("Hello World")
    assert_equal "squawk! Hello World", wickwall.last_tweet
  end
end

Ejecuta la prueba para asegurarte de que las dos últimas pruebas fallen con un error que contenga "NoMethodError: undefined method `squawk'", luego actualiza acts_as_yaffle.rb para que se vea así:

# yaffle/lib/yaffle/acts_as_yaffle.rb

module Yaffle
  module ActsAsYaffle
    extend ActiveSupport::Concern

    included do
      def squawk(string)
        write_attribute(self.class.yaffle_text_field, string.to_squawk)
      end
    end

    class_methods do
      def acts_as_yaffle(options = {})
        cattr_accessor :yaffle_text_field, default: (options[:yaffle_text_field] || :last_squawk).to_s
      end
    end
  end
end

# test/dummy/app/models/application_record.rb

class ApplicationRecord < ActiveRecord::Base
  include Yaffle::ActsAsYaffle

  self.abstract_class = true
end

Ejecuta bin/test una última vez, y deberías ver:

$ bin/test
...
6 runs, 6 assertions, 0 failures, 0 errors, 0 skips

NOTA: El uso de write_attribute para escribir en el campo en el modelo es solo un ejemplo de cómo un plugin puede interactuar con el modelo, y no siempre será el método correcto a usar. Por ejemplo, también podrías usar:

send("#{self.class.yaffle_text_field}=", string.to_squawk)

5 Generadores

Los generadores pueden ser incluidos en tu gema simplemente creándolos en un directorio lib/generators de tu plugin. Más información sobre la creación de generadores puede encontrarse en la Guía de Generadores.

6 Publicar tu Gema

Los plugins en desarrollo pueden ser fácilmente compartidos desde cualquier repositorio Git. Para compartir la gema Yaffle con otros, simplemente compromete el código a un repositorio Git (como GitHub) y agrega una línea al Gemfile de la aplicación en cuestión:

gem "yaffle", git: "https://github.com/rails/yaffle.git"

Después de ejecutar bundle install, la funcionalidad de tu gema estará disponible para la aplicación.

Cuando la gema esté lista para ser compartida como un lanzamiento formal, puede ser publicada en RubyGems.

Alternativamente, puedes beneficiarte de las tareas Rake de Bundler. Puedes ver una lista completa con lo siguiente:

$ bundle exec rake -T

$ bundle exec rake build
# Construir yaffle-0.1.0.gem en el directorio pkg

$ bundle exec rake install
# Construir e instalar yaffle-0.1.0.gem en las gemas del sistema

$ bundle exec rake release
# Crear etiqueta v0.1.0 y construir y subir yaffle-0.1.0.gem a Rubygems

Para más información sobre publicar gemas en RubyGems, consulta: Publicar tu gema.

7 Documentación RDoc

Una vez que tu plugin sea estable y estés listo para desplegar, hazle un favor a todos los demás y documenta tu plugin. Afortunadamente, escribir documentación para tu plugin es fácil.

El primer paso es actualizar el archivo README con información detallada sobre cómo usar tu plugin. Algunas cosas clave para incluir son:

  • Tu nombre
  • Cómo instalar
  • Cómo agregar la funcionalidad a la aplicación (varios ejemplos de casos de uso comunes)
  • Advertencias, consejos o trucos que puedan ayudar a los usuarios y ahorrarles tiempo

Una vez que tu README esté sólido, revisa y agrega comentarios RDoc a todos los métodos que los desarrolladores usarán. También es habitual agregar comentarios # :nodoc: a aquellas partes del código que no están incluidas en la API pública.

Una vez que tus comentarios estén listos, navega a tu directorio de plugins y ejecuta:

$ bundle exec rake rdoc
